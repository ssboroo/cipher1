# NARF Baseline Benchmark

## Purpose

This benchmark provides a deterministic, dependency-free first measurement of the NEXUS Adaptive Residual Transform (NARF). It reports encoded size and local encode/decode timing for five synthetic workloads.

It is an engineering baseline, not evidence that NARF is competitive with established compressors. The included pair-RLE implementation is intentionally simple and is used only as a size reference.

## Run

From the repository root:

```bash
cargo bench -p nexus-transform --bench narf_baseline
```

The executable writes CSV to standard output with these columns:

- `dataset`: workload identifier.
- `input_bytes`, `narf_bytes`, `identity_bytes`, `pair_rle_bytes`: exact byte counts.
- `narf_ratio`: NARF encoded bytes divided by input bytes.
- `encode_ns_per_byte`, `decode_ns_per_byte`: elapsed nanoseconds divided by total processed input bytes.

## Workloads

- Repeated byte: a single repeated value.
- Periodic: a four-byte repeating pattern.
- Ramp: byte values cycling from 0 through 255.
- Text-like: a deterministic repeated English-character sequence.
- Deterministic random: xorshift32-generated bytes with a fixed seed.

Each workload is 16 KiB. Timing uses five iterations and `std::time::Instant`; results are machine- and load-dependent.

## Interpretation rules

1. Never compare timing numbers across different machines as if they were controlled experiments.
2. Run at least five independent process invocations on an otherwise idle machine before reporting timing summaries.
3. Record CPU model, operating system, Rust version, target triple, build flags, and commit SHA with any published result.
4. Compare against optimized LZ4, Zstandard, and Brotli implementations in a separate benchmark harness before making broad compression claims.
5. Include framing and metadata in every size comparison.
6. Keep raw CSV output with the experiment record.

## Current limitation

This first harness does not yet measure peak memory, energy, streaming latency, or statistical confidence intervals. It does not establish a world-first result, a universal compression advantage, or production readiness.
