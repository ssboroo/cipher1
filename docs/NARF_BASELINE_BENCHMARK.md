# NARF Baseline Benchmark

## Purpose

This benchmark compares the NEXUS Adaptive Residual Transform (NARF) with LZ4, Zstandard, Brotli, identity, and a deliberately simple pair-RLE size reference across five deterministic synthetic workloads.

It is an engineering baseline, not evidence that NARF is competitive with established compressors. Codec libraries are benchmark-only development dependencies and are not part of the runtime crate dependency graph.

## Run

From the repository root:

```bash
cargo bench -p nexus-transform --bench narf_baseline
```

The executable writes CSV to standard output with these columns:

- `dataset`: workload identifier.
- `input_bytes`, `identity_bytes`, `narf_bytes`, `narf_ratio`, `lz4_bytes`, `zstd_bytes`, `brotli_bytes`, `pair_rle_bytes`: exact byte counts and NARF-to-input size ratio. Codec-specific framing is included; pair-RLE is a payload-only size reference.
- Per-codec encode and decode nanoseconds per input byte for NARF, LZ4, Zstandard, and Brotli.

## Workloads

- Repeated byte: a single repeated value.
- Periodic: a four-byte repeating pattern.
- Ramp: byte values cycling from 0 through 255.
- Text-like: a deterministic repeated English-character sequence.
- Deterministic random: xorshift32-generated bytes with a fixed seed.

Each workload is 16 KiB. Timing uses two warm-up passes and ten measured iterations with `std::time::Instant`; results are machine- and load-dependent. LZ4 uses `lz4_flex::compress_prepend_size`, Zstandard uses bulk compression level 3, and Brotli uses quality 5 with a 22-bit window. The harness verifies every codec's round trip before timing.

## Interpretation rules

1. Never compare timing numbers across different machines as if they were controlled experiments.
2. Run at least five independent process invocations on an otherwise idle machine before reporting timing summaries.
3. Record CPU model, operating system, Rust version, target triple, build flags, and commit SHA with any published result.
4. Treat these single-process measurements as screening data only; use multiple independent runs, confidence intervals, representative public corpora, and matched production settings before making claims.
5. Include framing and metadata in every size comparison.
6. Keep raw CSV output with the experiment record.

## Current limitation

The harness does not yet measure peak memory, energy, streaming latency, or statistical confidence intervals. Synthetic workloads are not representative of all production data. It does not establish a world-first result, a universal compression advantage, or production readiness.
